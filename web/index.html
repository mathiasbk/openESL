OpenESL

Source

Open firmware for e-paper shelf labels

OpenESL runs on SoluM ZBS243 tags (2.9" and 1.54", black and white) and an ESP32-C6 access point. The access point is a plain HTTP API: any software can put text on a tag by its MAC, and the AP sends it to the tag over 802.15.4 radio. This page has the tools to design the labels and to put the firmware on the hardware, all in the browser.

How it fits together

  1. Flash the AP on an ESP32-C6 and connect it to your computer or network. The Set up tab explains the first start, the WiFi and the API token.
  2. Flash the tags one by one in the jig. Each tag gets its MAC written to its info page and starts polling the AP.
  3. Design the layouts and upload the layout file to the AP with PUT /api/layouts/{model}. The tags download it over the radio.
  4. Send content from your own software with PUT /api/tags/{mac}, naming a layout and its fields (see API).
  5. Keep it running: GET /api/health lists the tags that need attention, and a webhook posts the same report when it changes; "at" schedules prices for a given time; POST /api/ota updates the AP's firmware without a cable, keeping its stored tags; esl-client tag-ota sends new tag firmware to the tags over the radio; esl-client log logs a long-term test; esl-client backup and restore move the stored tags, layout files and settings to a file and onto another AP.

What you need

  • Chrome or Edge on a computer for flashing (Web Serial). The designer works in any modern browser.
  • For tags: a Wemos D1 mini with atc1441's ZBS_Flasher, and a pogo-pin jig.
  • For the AP: an ESP32-C6 board with USB.

Setting up and running the AP: the Set up tab. API documentation: the API tab. Source and the radio protocol: github.com/mathiasbk/openesl.

Keys and tips
  • Drag a box to move it, drag its corner to resize. It snaps to the screen's edges and centre and to the other boxes; hold Alt to place it freely.
  • ← → ↑ ↓ move the selected box 1 px (Shift: 10 px). Tab picks the next box, Esc deselects, Delete removes it, Ctrl+D duplicates it, Ctrl+C and Ctrl+V copy it to another layout.
  • Ctrl+Z undoes, Ctrl+Shift+Z redoes.
  • Lines are thin boxes. For white text on black, put white text on a black box, or use inverted text.
  • The preview is drawn by the tag's own code and the file is checked by the AP's own compiler, so what you see is what the tag shows.

    Flash the access point (ESP32-C6)
    
      
    Connect the ESP32-C6 board by USB and press the button. Chrome or Edge on a computer is needed (Web Serial). If the board is not found, hold BOOT while you plug it in.

    First start
    
      
      
        
    1. Flash the AP (Flash AP) and leave it plugged into USB, or power it from a charger. Right after flashing, the Flash AP tab can give it your WiFi and an API token over the same cable; then skip to step 4.
      2. 
        
    2. Join its setup network. An AP with no WiFi saved opens an open network named openesl-XXXX (the last digits of its MAC). Join it with a phone or laptop: the phone's "sign in to network" page opens the setup form by itself; otherwise open http://192.168.4.1/setup. If the phone cannot join it, set the WiFi and token over USB above instead.
      3. 
        
    3. Fill in the form: pick your WiFi from the scan list, enter its password, and choose an API token (8 to 128 characters, letters, digits and punctuation, no spaces). The AP saves all three and joins your network at once; the setup network closes a minute later.
      4. 
        
    4. Find it on your network at http://openesl.local/ (mDNS; the name is ESL_MDNS_HOSTNAME in menuconfig) or at the IP your router gave it. The page at / is a read-only status page with all tags, and needs no token.
      5. 
        
    5. Try the API: curl -H "Authorization: Bearer <token>" http://openesl.local/api/tags, or python3 tools/esl-client/esl_client.py --url http://openesl.local --token <token> status.
      6. 
      
    
      
    No WiFi? The AP works over its USB port alone: esl_client.py --serial /dev/ttyACM0 status speaks the same API through the serial port, with no token. The WiFi and token can also be set that way: esl_client.py --serial /dev/ttyACM0 wifi "Network" --password "..." --new-token "...".
    
    
    

    
    
      
    The API token
    
      
    One shared secret for the whole AP. There are no users or roles: whoever has the token can read and change everything, so treat it like a password and keep the AP on your local network or VPN (the API is plain HTTP, there is no HTTPS).
    
      
      
        
    • Where it is set. The setup form, or "WiFi and API token over USB" above (also right after flashing, on the Flash AP tab), writes it to the AP's flash (NVS, cfg/token). A token can also be built into the firmware with ESL_API_TOKEN in menuconfig; the flash value wins when both exist. There is no default: with no token set, every API request gets 401 and the AP logs an error at start.
      • 
        
    • How it is sent. Authorization: Bearer <token> on every request to /api/..., also POST /api/ota. esl-client takes it as --token or the OPENESL_TOKEN environment variable.
      • 
        
    • What needs no token. The status page at / (it only reads; ESL_STATUS_PAGE in menuconfig turns it off) and the USB serial port: whoever has the cable has the device.
      • 
        
    • Wrong tokens lock the API. Five wrong tokens in a row lock the HTTP API for 60 seconds: every request, even with the right token, answers 429 with the seconds left. Wrong tokens in the setup form count in the same lock. The USB port is never locked.
      • 
        
    • Changing it. Over USB: "WiFi and API token over USB" above with only a new token, or esl_client.py --serial /dev/ttyACM0 wifi --new-token "..."; no old token is needed, since whoever has the cable has the device. Over WiFi: PUT /api/wifi with {"token": "..."} and the current token, or open the setup form (it is linked from the status page, or reachable on the setup network) and enter the current token and a new one. Once a token is set, the form asks for it before changing anything, so an open setup network only lets strangers configure an AP that has no token yet. ESL_WIFI_SETUP_PASSWORD in menuconfig puts WPA2 on the setup network as well.
      • 
        
    • Lost it? The token cannot be read back, but a new one can be set over USB at any time, as above. Nothing stored is lost.
      • 
      
    
    
    

    
    
      
    WiFi
    
      
      
        
    • The saved network and the token are kept in flash across restarts and firmware updates over the API (POST /api/ota). Erasing the flash clears them.
      • 
        
    • If the saved network gives no IP for 180 seconds (ESL_WIFI_SETUP_AFTER_S), the AP opens the setup network again next to it, so a changed WiFi password can be fixed from a phone without a cable. It keeps retrying the saved network every 20 seconds meanwhile, and closes the setup network a minute after it has joined.
      • 
        
    • GET /api/wifi shows the state and the last scan; PUT /api/wifi, or esl-client wifi SSID --password ..., changes the network (wifi "" forgets it and opens the setup network). Over WiFi the AP drops the old network at once, so do that over USB or on the setup form.
      • 
        
    • The tags do not use WiFi: they talk to the AP over 802.15.4 radio on channel 25 (ESL_CHANNEL), which WiFi 2.4 GHz and Zigbee networks share. The AP's WiFi and radio coexist on the same chip.
      • 
      
    
    
    

    
    
      
    Running it
    
      
      
        
    • Content. Your software sends text per tag with PUT /api/tags/{mac}, or many at once with PUT /api/tags; the AP stores it and hands it to the tag at its next poll (about a minute). "at" in the request sets it at a given time, so a price change can be sent the day before. The API tab has every call, and tools/esl-client is a complete command-line client (price, text, sync prices.csv from an Excel export, --at).
      • 
        
    • Health. GET /api/health lists the tags that need attention (silent, not yet seen, low battery, drawing failed, layout file rejected), and webhook in PUT /api/config makes the AP POST the same report to your software whenever it changes. The status page shows the same flags.
      • 
        
    • Updates. Each release has an openesl-ap-esp32c6-<version>-ota.bin: esl-client ota that.bin --wait writes it over the API, the AP restarts into it keeping its tags, layout files, WiFi and token, and the client reports whether the new version runs. If the new firmware does not start, the AP falls back to the old one by itself. The Firmware card on the Dashboard tab sends the same file from this page. Tags are updated over the radio: esl-client tag-ota openesl-tag-<model>-<version>-ota.bin (or the same card) gives the image to the AP, each tag of that model fetches it a part at a time at its normal polls, keeps showing its price meanwhile, and restarts into it. On the 1.54" jig tag a 54 KB image took 6–8 polls (about 7–8 minutes at one poll a minute). esl-client tag-ota without a file shows how many tags are updated, still waiting, or failed. A tag needs one pass in the jig with this firmware first (Flash tag), and the AP one flash over USB for the tag firmware storage.
      • 
        
    • Backup. esl-client backup ap.json saves the tags' content and settings, the layout files, the default poll interval, the webhook and the schedule; restore ap.json puts them onto the same or another AP. The WiFi and the token are not in it.
      • 
        
    • Long-term test. esl-client log week.csv records every tag once a minute, and report week.csv sums up gaps, battery and AP restarts.
